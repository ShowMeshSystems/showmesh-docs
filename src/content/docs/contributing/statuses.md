---
title: Status vocabulary
description: Stable meanings for availability and maturity labels across all human documentation.
---

These labels describe documented functionality. They do not replace the main repository's research evidence levels or build-track statuses.

## Available

Implemented, supported for current use, and suitable for normal users in the documented development state. “Available” does not claim show-hardware validation unless the page says so separately.

## Experimental — Active Development

Implemented enough to exist or be exercised, but still changing materially. Behavior, configuration, or interfaces may move. Users must not depend on stability.

## Experimental — Ready for Testing

Substantially complete for its current scope and intentionally available for real-world testing and feedback, but not yet broadly supported or stable.

## Planned

Design-approved or intended future functionality that is not currently available. A Planned page must separate the future model from the working behavior available now. Planned material must not contain runnable steps that imply implementation exists.

## Advanced

Available functionality that assumes deeper ShowMesh or system knowledge, or carries more operational complexity. Advanced describes audience and risk, not instability; combine it with an experimental label if both apply.

## Deprecated

Still present but should not be chosen for a new deployment. State the replacement and removal/migration expectations. This label is reserved now so future deprecations use one meaning.

## Changing a label

Do not promote a page based on intent or a task status. Verify the behavior against the documented code state and record the evidence that justifies the change. If only part of a page has a different maturity, label that part rather than weakening the meaning of the page-level label.
